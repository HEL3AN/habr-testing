# Чек-лист: Регистрация и авторизация

**URL регистрации:** https://account.habr.com/register/
**URL авторизации:** https://account.habr.com/login/
**Цель раздела:** регистрация нового пользователя, вход существующего пользователя, восстановление пароля.

---

## 1. Общее отображение страниц

- [ ] Страница регистрации открывается без ошибок
- [ ] Страница авторизации открывается без ошибок
- [ ] Отсутствуют ошибки JS в консоли
- [ ] Корректно отображается логотип Habr (кликабелен → ведёт на главную)
- [ ] На странице регистрации присутствует ссылка «Войти» (и наоборот)
- [ ] Заголовок вкладки соответствует разделу

## 2. Регистрация: поля формы

- [ ] Присутствует поле «Никнейм»
- [ ] Присутствует поле «Email»
- [ ] Присутствует поле «Пароль»
- [ ] Присутствует поле подтверждения пароля (или единое поле с показом)
- [ ] Присутствует чекбокс согласия с правилами и политикой конфиденциальности
- [ ] У каждого поля есть placeholder или подпись
- [ ] У полей паролей есть иконка «показать/скрыть»
- [ ] Поля поддерживают автозаполнение из браузера

## 3. Регистрация: валидация полей

### Никнейм
- [ ] Невозможно зарегистрироваться с пустым никнеймом
- [ ] Никнейм короче минимальной длины — ошибка
- [ ] Никнейм длиннее максимальной длины — ошибка
- [ ] Запрещённые символы (пробелы, спецсимволы) — ошибка
- [ ] Уже занятый никнейм — ошибка с понятным сообщением

### Email
- [ ] Невозможно отправить форму с пустым email
- [ ] Email без `@` отклоняется
- [ ] Email без домена (`user@`) отклоняется
- [ ] Email без локальной части (`@domain.ru`) отклоняется
- [ ] Email с недопустимыми символами отклоняется
- [ ] Уже зарегистрированный email — ошибка
- [ ] Email с пробелами в начале/конце обрабатывается корректно (trim)

### Пароль
- [ ] Пустой пароль не принимается
- [ ] Слишком короткий пароль (меньше минимума) отклоняется
- [ ] Слишком длинный пароль обрабатывается корректно
- [ ] Требования к сложности отображаются и проверяются
- [ ] Несовпадающие пароль и подтверждение — ошибка
- [ ] Иконка «показать пароль» переключает видимость символов

### Согласие с правилами
- [ ] Без отметки чекбокса согласия регистрация невозможна

## 4. Регистрация: успешный сценарий

- [ ] После корректного заполнения формы пользователь создаётся
- [ ] На email отправляется письмо с подтверждением
- [ ] Ссылка из письма подтверждает email
- [ ] Повторный переход по ссылке подтверждения отрабатывает корректно
- [ ] Просроченная ссылка подтверждения обрабатывается с понятным сообщением
- [ ] После регистрации пользователь автоматически авторизован (или перенаправлен на форму входа)
- [ ] Новому пользователю назначается стартовая карма/рейтинг согласно правилам

## 5. Авторизация: поля и валидация

- [ ] Присутствует поле «Email или никнейм»
- [ ] Присутствует поле «Пароль»
- [ ] Присутствует чекбокс «Запомнить меня» (если предусмотрен)
- [ ] Кнопка входа неактивна или возвращает ошибку при пустых полях
- [ ] При неверном email — ошибка «Пользователь не найден» или единое сообщение
- [ ] При неверном пароле — ошибка «Неверный пароль» или единое сообщение
- [ ] Сообщение об ошибке не раскрывает, что именно неверно (защита от перебора)
- [ ] После N неуспешных попыток входа появляется капча или временная блокировка

## 6. Авторизация: успешный сценарий

- [ ] При корректных данных пользователь успешно входит
- [ ] После входа происходит редирект на главную или последнюю просмотренную страницу
- [ ] Сессия сохраняется при перезагрузке страницы
- [ ] Сессия сохраняется в новой вкладке того же браузера
- [ ] При установленном «Запомнить меня» сессия живёт долго (cookie с длительным сроком)
- [ ] Без «Запомнить меня» сессия завершается после закрытия браузера

## 7. OAuth / соцсети

- [ ] Отображаются кнопки входа через GitHub, Google, VK, Apple и т. п. (актуальные провайдеры)
- [ ] Кнопка входа через каждого провайдера ведёт на корректную страницу авторизации
- [ ] При успешной авторизации через провайдера создаётся/связывается аккаунт Habr
- [ ] Отмена авторизации на стороне провайдера возвращает на страницу логина с понятным сообщением

## 8. Восстановление пароля

- [ ] Доступна ссылка «Забыли пароль?» на странице входа
- [ ] При вводе email отправляется письмо со ссылкой восстановления
- [ ] Для несуществующего email сообщение об отправке не раскрывает факт отсутствия аккаунта
- [ ] Ссылка восстановления одноразовая
- [ ] По ссылке открывается форма установки нового пароля
- [ ] Новый пароль проходит ту же валидацию, что и при регистрации
- [ ] После смены пароля все активные сессии завершаются (опционально, но желательно)
- [ ] Просроченная ссылка восстановления обрабатывается корректно

## 9. Выход из аккаунта (logout)

- [ ] Кнопка «Выйти» доступна в меню пользователя
- [ ] После выхода сессия завершается на всех вкладках
- [ ] После выхода защищённые страницы недоступны, происходит редирект на форму входа

## 10. Безопасность

- [ ] Все формы передаются по HTTPS
- [ ] Пароль не передаётся открытым текстом в URL/логах
- [ ] В DOM пароль маскирован
- [ ] При нажатии «Назад» после logout защищённая страница не доступна из кэша браузера
- [ ] Cookie сессии имеет флаги `HttpOnly` и `Secure`
- [ ] Форма защищена от CSRF (наличие токена)
- [ ] Двухфакторная аутентификация (если включена) работает корректно

## 11. Доступность и UX

- [ ] Навигация по формам с клавиатуры (Tab переключает поля в логичном порядке)
- [ ] Enter в поле пароля отправляет форму
- [ ] Ошибки валидации отображаются рядом с полем и понятны пользователю
- [ ] У полей с ошибкой есть визуальное выделение (цвет рамки/иконка)
- [ ] Сообщения об ошибках доступны для скринридеров (`aria-describedby`/`aria-live`)

## 12. Адаптивность

- [ ] Корректное отображение форм на десктопе
- [ ] Корректное отображение на планшете
- [ ] Корректное отображение на мобильном (поля занимают всю ширину, удобный размер кнопок)
